# 実機確認

## 実施条件

- ページ表示領域を **1920×960 CSS px、ブラウザーのズーム100%** にする。ウィンドウ外寸ではなくページの幅・高さを確認する。
- 全項目を実際の画面操作で実施する。CIで確認済みの決定的な規則は [自動テストとの対応](test-traceability.md) に従い、ここでは実環境でしか確認できない部分を実施する。
- Windowsのファイル・フォルダー・保存先・モデル・色選択ダイアログはactiveの実機確認対象だが、今回のダイアログを開かない確認では実行しない。画像はアプリのパス入力から読み込む。保存先が未設定のコピー保存は実行せず、その制約を報告する。
- 編集・上書き・削除には確認専用の画像コピーとプロジェクトを使う。
- 横長・縦長・正方形、PNG・JPEG・WebP、透過PNG、回転情報付きJPEG、長い日本語名、同名の別フォルダー画像、壊れた画像を用意する。4K画像と400画像の一覧も用意する。
- モデル確認には利用者が用意した画像と利用可能なモデルを使う。特定ファイル名、検出率、検出位置の精度評価は条件に含めない。
- モデルONで候補0件の場合、候補数だけで実行の有無を判断しない。設定と準備・実行状況を合わせて確認する。機材・モデル不足で実施できない操作は完了報告で明記する。
- 下記の共通確認を各項目で実施する。判定欄・記録欄は設けない。
- 画面操作の成功だけで終了しない。読み込みは通信と画像表示、保存は対象名と出力内容、PJ操作は再開後のデータまで照合する。

## 全項目共通確認

| 観点 | 手順 | 期待値 |
| --- | --- | --- |
| 配置 | 操作前後の1920×960画面を見る | ラベル・数値・アイコン・ボタンが重ならない。操作と閉じるボタンが画面内にある。長い名前は省略または折返しになり、隣の操作を覆わない |
| 状態 | ON/OFF、無効状態、件数、画像名を見る | 対象画像名と件数が一致する。ON/OFFを文字または押下状態で区別できる。無効ボタンで処理を開始しない |
| 通信 | 通信が発生する項目ではNetworkのログ保持をONにし、要求のURL・対象ID・状態・応答を確認 | 読み込み対象の画像・マスクと操作APIが成功する。200でもエラーJSON・空画像なら成功扱いにしない。404・409・500・通信切断は原因と画面の案内を突合する。画像切替で不要になった要求の取消は区別する |
| 保存結果 | ファイル・ZIPを出力する項目では出力を開き、予定した名前一覧・件数・寸法・モザイクと除外の位置を照合 | 対象を全件出力し、対象外を出力しない。除外と重なる部分はモザイクをかけず、加工範囲外の画像と編集データを保持する |
| 永続化 | 名前付きPJの状態を変更する項目ではPJを開き直し、対象画像を選ぶ。削除操作では管理表と残るPJを確認 | 保存した候補・手描き・枠・ON/OFF・強制・確認済み・非表示を復元する。取消した変更は残らず、削除したデータは復活しない |
| キーボード | Tabで移動しEnterまたはSpaceで実行する | フォーカス枠が見える。モーダル内から背景へ移動しない。閉じると起点へ戻る |
| 応答 | 操作直後と処理中の画面を見る | 操作状態または進捗が表示される。ポインター移動と許可されたスクロールに追従する |
| メモリ | 同じ状態から操作と取消・復帰を5回繰り返し、ブラウザーとMozarieのRAM、GPU使用時の専用VRAMを開始前・処理中・終了後に見る | 初回準備後も終了後の使用量が回数に応じて増え続けない。閉じた画面・旧画像の保持が積み重ならない。GPU検出終了後は推論用VRAMが減る。CPUモデルの再利用キャッシュは毎回の解放を要求しない |
| 負荷 | Performance MonitorとタスクマネージャーでCPU・メモリを操作中と終了後に見る | 終了後にCPU高負荷が続かない。同一操作の重複通信・モデル再準備・全件取得が回数に応じて増えない。取消後に新しい画像の処理を開始しない |
| 描画 | 描画中とダイアログ5回開閉後の応答を比較する | 描画がマウスを離すまで保留されない。開閉回数に応じて描画・スクロール遅延が増えない。待機中にDOM・イベントリスナーが増え続けない |
| 分離 | 別画像と別PJの状態を見る | 対象外の画像・PJのモザイク、除外、確認状態、履歴が変わらない |

観察方法：[Chrome Performance Monitor](https://developer.chrome.com/docs/devtools/performance-monitor)、[メモリ問題の調査](https://developer.chrome.com/docs/devtools/memory-problems)。
